# Intune / Group Policy

You can lock down any of the settings in [Configuration](/configuration) by setting registry
values under `HKLM\SOFTWARE\Policies\OncallBusyBarAgent`, with one subkey per section:

```txt
HKLM\SOFTWARE\Policies\OncallBusyBarAgent\Graph      (values: ClientId, TenantId, PollIntervalSeconds)
HKLM\SOFTWARE\Policies\OncallBusyBarAgent\Mic         (values: Enabled, PollIntervalSeconds)
HKLM\SOFTWARE\Policies\OncallBusyBarAgent\BusyBar     (values: Address, HttpAccessPassword)
```

Only set the values you want to enforce. Anything you leave out comes from the user's own
`appsettings.json`. Set `Enabled` as a string (`true` or `false`). The intervals can be a string
or a DWORD, whichever your deployment tool makes easier.

It doesn't matter how the values get there. An Intune custom OMA-URI profile, a script in a Win32
app deployment and Group Policy all work the same, because the app just reads the registry.

## Administrative template (ADMX/ADML)

If you'd rather point and click than write OMA-URIs or scripts, the repo includes an
administrative template in
[`admx/`](https://github.com/homotechsual/oncall-busybar-agent/tree/main/admx):
`OncallBusyBarAgent.admx` and its language file, `en-US/OncallBusyBarAgent.adml`. It gives you
the same registry values as friendly settings in Intune's Settings Catalog or the Group Policy
Editor.

### Import into Intune

1. Go to **Devices** → **Manage devices** → **Configuration**, open the **Import ADMX** tab and
   choose **Import**.
2. Upload `OncallBusyBarAgent.admx` as the ADMX file and `en-US/OncallBusyBarAgent.adml` as the
   ADML file for `en-US`.
3. Create a **Settings Catalog** profile and search for "BUSY Bar on call agent". The seven
   settings are grouped under **Microsoft Graph sign-in**, **Microphone fallback** and **BUSY Bar
   device**.
4. Set the ones you want to enforce and assign the profile to your devices. Anything left as "Not
   configured" comes from the user's own `appsettings.json`.

**Updating the template later:** Intune won't accept a changed ADMX with the same namespace while
the old one is still in use. Either delete the profiles that use it and the old ADMX first, or
give the new version a different `policyNamespaces` namespace, for example by adding a version
number.

### Use with Group Policy instead

Copy `OncallBusyBarAgent.admx` to `%SystemRoot%\PolicyDefinitions` and
`en-US\OncallBusyBarAgent.adml` to `%SystemRoot%\PolicyDefinitions\en-US`, or to your domain's
central store if you have one. The settings then appear under **Computer Configuration →
Administrative Templates → BUSY Bar on call agent**.

### What the template covers

The template has the seven settings from [Configuration](/configuration): `Graph:ClientId`,
`Graph:TenantId`, `Graph:PollIntervalSeconds`, `Mic:Enabled`, `Mic:PollIntervalSeconds`,
`BusyBar:Address` and `BusyBar:HttpAccessPassword`. If a later version adds a setting before the
template catches up, you can still set it directly in the registry under the same key.
