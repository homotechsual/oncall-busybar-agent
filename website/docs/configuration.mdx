# Configuration

Settings load in four layers, each overriding the one before it:

1. The bundled `src/OncallAgent/appsettings.json`: factory defaults, including the shared
   `Graph:ClientId` described in [Sign in](/#sign-in).
2. Environment variables (double underscore nesting, for example `Graph__ClientId`).
3. A per-user, writable copy at `%LOCALAPPDATA%\oncall-busybar-agent\appsettings.json`, created
   automatically from the bundled defaults the first time the app runs. Edit this file (not the
   one under `src/OncallAgent`) to change settings after that first run; it survives updates,
   which the bundled file's location does not once the app is installed as an MSIX package.
   The MSIX version keeps this file inside its package data instead, at
   `%LOCALAPPDATA%\Packages\MJCOLtd.OnCallBusyBarAgent_<id>\LocalCache\Local\oncall-busybar-agent\`,
   and Windows removes it on uninstall. Either way, **Open settings file** in the tray icon's
   menu opens the right one. Restart the agent after saving.
4. An IT-managed registry policy, for organizations deploying this via Intune or another MDM tool.
   See [Intune / Group Policy](/intune-group-policy). This always wins over the file above.

| Key | Default | Description |
| --- | --- | --- |
| `Graph:ClientId` | (shared default) | The Entra app's (public) client ID. |
| `Graph:TenantId` | `organizations` | Which tenants can sign in; matches the app registration's account type. |
| `Graph:PollIntervalSeconds` | `30` | How often to poll presence and the calendar (both are polled together on every cycle). |
| `Mic:Enabled` | `true` | Whether the local microphone check runs at all. With it off, scheduled meetings are only detected from Teams call presence. |
| `Mic:PollIntervalSeconds` | `5` | How often to check local microphone activity. |
| `BusyBar:Address` | `10.0.4.20` | Network address of the BUSY Bar device. |
| `BusyBar:HttpAccessPassword` | (empty) | The device's HTTP API password, if you connect over Wi-Fi and have set one. Not needed over USB. |

### Connecting over Wi-Fi

By default the agent talks to the BUSY Bar over USB, at `10.0.4.20`. To use Wi-Fi instead, enable
the HTTP API on the device, set `BusyBar:Address` to the device's IP address or hostname, and, if
you gave the HTTP API a password, put it in `BusyBar:HttpAccessPassword`. Without a password,
anyone on the same network can control the device, so setting one is worth it.

The password is stored as plain text in `appsettings.json` or the registry policy. The device's
HTTP API is plain HTTP, so the password also crosses your local network unencrypted. It keeps out
casual access, not someone who can watch your network traffic.
