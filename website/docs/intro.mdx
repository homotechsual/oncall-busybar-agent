# Getting started

**BUSY Bar on call agent** is a Windows tray app that runs your BUSY Bar's timer while you're on a
Microsoft Teams call. The timer starts when a call starts and stops when it ends. For a scheduled
meeting, it counts down to the meeting's end time.

Teams presence from Microsoft Graph is the main signal, with a calendar lookup for the meeting's
end time. For calls Teams doesn't report, the app falls back to checking whether your microphone
is in use. A meeting on your calendar only counts while your microphone is in use, so the timer
stops if you leave early.

## Sign in

There's nothing to set up before you sign in. The app ships with a shared, multi-tenant Entra app
registration (the `Graph:ClientId` in `appsettings.json`). If your organization requires admin
consent for third-party apps, ask an Entra admin to grant consent for the delegated
`Presence.Read` and `Calendars.ReadBasic` permissions. After that, anyone in your tenant can sign
in.

## Optional: register your own Entra app

You only need this if the shared registration doesn't work for you. That's usually because
Conditional Access blocks consent to multi-tenant apps, or because you'd rather use a registration
you control. Create one in [the Entra admin center](https://entra.microsoft.com/):

1. Go to **App registrations** and choose **New registration**.
2. Give it a name, for example `oncall-busybar-agent`.
3. Under **Supported account types**, choose **Accounts in any organizational directory** if you
   want people in other tenants to be able to use it, or **Accounts in this organizational
   directory only** to keep it to your own tenant.
4. Under **Redirect URI**, choose the **Mobile and desktop applications** platform and add
   `http://localhost`.
5. Add a second redirect URI on the same platform for the Windows sign-in broker:
   `ms-appx-web://Microsoft.AAD.BrokerPlugin/<client-id>`. You'll fill in the client ID in step 7.
   Without this, sign-in fails with `AADSTS50011: The redirect URI ... does not match the redirect
   URIs configured for the application`.
6. Under **API permissions**, add the Microsoft Graph delegated permissions `Presence.Read` and
   `Calendars.ReadBasic`.
7. Copy the **Application (client) ID** from the Overview page and put it into the redirect URI
   from step 5.
8. Set `Graph:ClientId` to your new client ID, and `Graph:TenantId` too if you limited the account
   types in step 3. Your own `appsettings.json` is simplest for one machine. To roll it out to a
   whole organization, use [Intune or Group Policy](/intune-group-policy). See
   [Configuration](/configuration) for all the options.
